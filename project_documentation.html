1. Project Overview

The HelpDeskTicketManagement System is a full-stack enterprise web application designed to streamline software, hardware, and network support requests across an organization. Built on .NET 8.0, the project adheres to standard software engineering patterns, implementing a decoupled ASP.NET Core Web API service backend, an ASP.NET Core MVC web application client, and an xUnit automated unit testing project.

The architecture follows a strict separation of concerns through the Repository Pattern and Entity Framework Core (EF Core). The MVC application interacts exclusively with the Web API via an asynchronous HttpClient service layer, ensuring complete isolation of database access and security boundaries.

2. Objective of the Application

The primary objective of the Help Desk Ticket Management System is to provide employees and IT staff with an intuitive, efficient platform to record, track, update, and resolve internal support tickets.

  • Ticket Lifecycle Management: Enable employees to raise tickets for IT issues and track resolution state.
  • Tiered Priority Categorization: Categorize support requests into Low, Medium, and High priority queues.
  • Status Workflow Tracking: Monitor ticket progression across three distinct states: Open, In Progress, and Closed.
  • Decoupled Architecture: Enforce strict SOA (Service-Oriented Architecture) where frontend clients communicate exclusively via RESTful APIs.
  • Automated Quality Assurance: Guarantee code stability and regression-free controller execution via isolated unit tests using xUnit and Moq.

4. Functional Modules

The solution is divided into three distinct solution projects:

Module A: HelpDesk.Api (ASP.NET Core Web API Project)

  • Model Layer (Ticket.cs): Defines the core domain entity representing support requests.
  • Data Context Layer (HelpDeskDbContext.cs): EF Core DbContext managing SQLite database transactions and initial seed data.
  • Repository Layer (ITicketRepository & TicketRepository): Encapsulates all LINQ database operations asynchronously.
  • API Controller Layer (TicketController.cs): Exposes REST API endpoints returning standard HTTP status codes (200 OK, 400 Bad Request, 404 Not Found).

Module B: HelpDesk.Mvc (ASP.NET Core MVC Client Project)

  • Service Layer (TicketService.cs): Implements ITicketService to execute asynchronous HTTP GET, POST, PUT, and DELETE calls to the Web API.
  • ViewModel Layer (TicketViewModel, DashboardViewModel, TicketFilterViewModel): Structures data for Razor view rendering and user form validation.
  • UI Controllers & Views (TicketController & Razor Views): Renders Dashboard, View All, Ticket Details, Raise Ticket, Edit Ticket, and Filter Status views.

Module C: HelpDesk.Tests (xUnit Test Project)

  • Contains isolated unit tests mocking ITicketRepository using Moq to verify HTTP response types without accessing a real database.

5. Database Table Structure

The primary entity stored in the database is the Ticket table:

Column Name Data Type Constraints Allowed / Default Values Description
Id INTEGER Primary Key, Auto-Increment 1, 2, 3... Unique ticket identifier
Title TEXT (NVARCHAR) NOT NULL, Max 100 User string input Short summary of the issue
Description TEXT (NVARCHAR) NOT NULL, Max 1000 User string input Detailed description of issue
Priority TEXT (NVARCHAR) NOT NULL Low, Medium, High Ticket priority level
Status TEXT (NVARCHAR) NOT NULL Open, In Progress, Closed Current status state
RaisedBy TEXT (NVARCHAR) NOT NULL User string input Name/ID of employee
CreatedDate DATETIME NOT NULL UTC Timestamp Creation timestamp

6. Business & Validation Rules

  • Status Hardcoding Rule: When raising a new ticket via the MVC UI, the Status property is automatically hardcoded to Open.
  • Priority Dropdown Rule: Users must explicitly select a priority level from a predefined dropdown containing Low, Medium, and High.
  • Status Progression Rule: Only the Edit Ticket module allows updating ticket status to In Progress or Closed.
  • Decoupling Enforcement: The MVC project must not reference EF Core or DbContext; all data access is routed through the Web API endpoint via HttpClient.
  • Form Validation Rules:
    • Title: Required field, length must be between 1 and 100 characters.
    • Description: Required field, length must be between 1 and 1000 characters.
    • RaisedBy: Required field.

7. Web API Endpoint Specification

HTTP Method API Endpoint URL Request Payload Success Response Description
GET /api/Ticket/All None 200 OK (List<Ticket>) Retrieves all support tickets
GET /api/Ticket/{id} None 200 OK / 404 Not Found Retrieves ticket by ID
POST /api/Ticket JSON Ticket Object 200 OK (Ticket ID) / 400 Bad Creates a new support ticket
PUT /api/Ticket/{id} JSON Ticket Object 200 OK / 404 Not Found Updates existing ticket
DELETE /api/Ticket/{id} None 200 OK / 404 Not Found Deletes ticket by ID
GET /api/Ticket/Status/{status} None 200 OK (List<Ticket>) Filters tickets by status
